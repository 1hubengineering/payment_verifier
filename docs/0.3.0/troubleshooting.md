Start with the [result or operation error](configuration.md) and its stage.
Keep inconclusive payments pending and follow [original-key recovery](retries.md)
when the submission or commit outcome is uncertain.

| Finding                                                                                                      | What to check                                                                                                                                                                                                                                                                      |
| ------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PROVIDER_TIMEOUT`, `PROVIDER_NETWORK_ERROR`                                                                 | Check outbound routing, provider availability, and deadlines from the actual worker. A timeout alone does not identify an IP or geographic restriction. Compare approved connectivity paths before choosing a deployment route.                                                    |
| `PROVIDER_DNS_ERROR`, `DESTINATION_BLOCKED`                                                                  | Check the worker resolver and egress policy. The built-in direct transport requires public IPv4 and blocks unsafe destinations.                                                                                                                                                    |
| `PROVIDER_TLS_ERROR`                                                                                         | Check the backend clock, CA trust, hostname and TLS route. Keep certificate verification enabled.                                                                                                                                                                                  |
| `PROVIDER_HTTP_ERROR`, `PROVIDER_RATE_LIMITED`, `PROVIDER_BUSY`                                              | An unexplained 404 remains unavailable. Other unexpected responses can indicate provider or transport changes. Honor retryability and delay hints, keep concurrency bounded and investigate recurring errors. A true `NOT_FOUND` requires recognized provider evidence of absence. |
| `INVALID_PROVIDER_RESPONSE`, `RECEIPT_TOO_LARGE`, `UNSUPPORTED_RECEIPT_FORMAT`                               | Check headers, response size and parser support with a sanitized fixture. Review provider changes before widening any limits.                                                                                                                                                      |
| `RECEIPT_BROWSER_UNAVAILABLE`                                                                                | Check the pinned Playwright/Chromium pair, OS dependencies, service user, executable and sandbox support. Run the offline `checkCbeBrowser()` diagnostic in that runtime.                                                                                                          |
| `RECEIPT_RENDER_TIMEOUT`                                                                                     | Check CBE worker resource limits, contention and rendering deadline. Escalate if it continues on locally supported fixtures.                                                                                                                                                       |
| `REQUIRED_FIELD_MISSING`, `INVALID_RECEIPT_FIELD`, `AMBIGUOUS_RECEIPT_FIELD`, `MULTIPLE_VERIFICATION_ISSUES` | Review the receipt layout and the configured expected fields. Use merchant review for missing details and derive expectations from trusted records.                                                                                                                                |
| `STORAGE_FAILURE`, `STORAGE_OUTCOME_UNKNOWN`, `CORRUPT_STATE`, `INCOMPATIBLE_STORE`                          | Check database health, active transaction, schema and release. Recover uncertain commits with the original key. Preserve claim records when restoring or migrating.                                                                                                                |
| `IDEMPOTENCY_CONFLICT`                                                                                       | Check whether the tenant, order and original locator agree with the request saved under that key. Resume the original request.                                                                                                                                                     |
| `RECEIPT_ALREADY_CLAIMED`                                                                                    | Look up the original authorized attempt and escalate disputes privately. Keep claim details out of responses to other customers.                                                                                                                                                   |

[Deployment and connectivity](../deployment.md) distinguishes local Chromium
checks, TLS-only diagnostics and authorized live receipt checks. The
[historical deployment report](../development/reports/v0.2.0-vps-validation.md)
records direct Telebirr timeouts from a VPS and successful retrieval via a
workstation tunnel. It establishes that behavior for the tested paths only.

Log a stage, code, internal correlation ID, provider name and coarse timing.
Keep raw SMS, receipt URLs, account details, idempotency keys, unfiltered
diagnostics and database errors out of routine logs.
