| Question                                   | Short answer                                                                                                                                                                                                                      |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Where does the customer's money go?        | Directly to the merchant's designated account or wallet. The SDK checks receipt evidence and records verification state. [Responsibilities](storage.md)                                                                           |
| Which evidence can I accept?               | Telebirr and CBE identifiers, official receipt URLs and SMS with supported locators. [Formats and examples](evidence.md)                                                                                                          |
| Can I reuse my database or schema?         | Reuse your database and supported client. Use the documented schema for a ready-made adapter or implement the storage contract over your own schema. [Storage and custom adapters](storage.md)                                    |
| What does `VERIFIED` establish?            | The official receipt passed the required checks and the claim became durable at the applicable transaction commit. [Guarantees and result fields](configuration.md)                                                               |
| Can the same transfer verify two orders?   | One shared store admits a single claim for a provider transaction. Independent stores cannot coordinate duplicate claims. [Duplicate scope](storage.md)                                                                           |
| What do I tell a customer after a timeout? | Keep the order pending. Say the receipt could not be checked yet and avoid asking for another payment. [Recovery and messaging](retries.md)                                                                                       |
| Which idempotency key should I reuse?      | Use the original key for uncertain completion. Use a fresh key only for a deliberate new observation after a known outcome. [Idempotency](retries.md#idempotency)                                                                 |
| Does the amount have to be exact?          | Yes by default. The host can configure bounded underpayment or overpayment allowances. [Amount policies](amounts.md)                                                                                                              |
| How can I learn or test without paying?    | Run the offline comparison, then exercise real storage with a synthetic provider. [Quickstart](quickstart.md) · [Testing modes](testing.md)                                                                                       |
| Where can I run it?                        | Use a supported Node ESM backend, with outbound provider connectivity and sandboxed Chromium for CBE. [Deployment](../deployment.md)                                                                                              |
| Can I upgrade an existing store?           | A valid 0.2.0 store can be retained, with all readers and writers upgraded together. Active 0.1.1 stores require a tested claim-preserving cutover. [Upgrade and rollback](../development/releases/0.3.0.md#upgrade-and-rollback) |
| Where are the exact imports and types?     | Find each published entry point and declaration in the [API reference](api.md).                                                                                                                                                   |
