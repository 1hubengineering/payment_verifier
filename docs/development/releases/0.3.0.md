## SDK changes

- Use `@1hubengineering/verifier/comparison` for browser-safe comparison and ETB
  functions. Receipt retrieval and atomic claims run in the Node.js backend.
- Reference text is case-sensitive and accepts up to 255 characters. A string
  containing only whitespace is rejected as an expectation. An explicit blank
  expectation requires `referenceRequired: false` and matches a blank or absent
  receipt note. A conflicting or invalid note still fails the check. Telebirr
  uses Customer Note and CBE uses Reason / Type of service.
- The CBE provider handles the data-backed receipt layout and exposes the offline
  `checkCbeBrowser` diagnostic. It requires the pinned Playwright version,
  matching Chromium, and a working OS sandbox. The Telebirr adapter supports
  its current note layout and optional host-configured SSH socket.
- `checkProviderConnectivity` tests TLS to the fixed official destinations
  without submitting a receipt. Malformed evidence on a bound idempotency key
  returns `IDEMPOTENCY_CONFLICT`. A receipt match leaves settlement and
  fulfillment with the host.

## Upgrade and rollback

Back up your store and replace the SDK across API processes and workers before
registering expectations that use the new reference rules. The 0.2.0 SQL schema
and payload version are unchanged. Records using references rejected by 0.2.0
may fail to open after a rollback. Use a compatible deployment and preserve all
claims written since the upgrade. Keep active 0.1.1 stores on their existing
runtime until a supported claim-preserving cutover is available.

The verification playground, benchmark runner, CLI, and worker are private
repository packages. The benchmark uses synthetic workloads and its separately
recorded environment. It does not establish live provider performance.

The [GitHub release](https://github.com/1hubengineering/payment_verifier/releases/tag/v0.3.0)
provides the source reference, test evidence, and archive checksums.
