SDK 0.2.0 candidate

Preview from source. The published guide and API reference cover SDK 0.1.1.

Install the published SDK

npm install @1hubengineering/verifier@0.1.1

To test 0.2.0 from source, run vp env install, pnpm install --frozen-lockfile, then pnpm build in a reviewed checkout. Use the workspace packages and a fresh test database. See the candidate integration example and API usage.

Receipt input and outcomes

For local candidate testing, use the workspace packages from a reviewed checkout. Hosts register an immutable ETB expectation before submitting an official receipt. Automatic input detection accepts Telebirr transaction IDs and CBE v2- receipt IDs, official receipt URLs, and SMS with an unambiguous identifier.

Results include VERIFIED, MISMATCH, NOT_FOUND, UNAVAILABLE, or INVALID_INPUT, plus a diagnostic code, stage, retryability and individual checks. An official receipt match leaves settlement and fulfillment with the host.

Browser interfaces can import detectPaymentInput from @1hubengineering/verifier/input and use pure SDK comparison and ETB functions from @1hubengineering/verifier/comparison. Official retrieval and atomic claims run on the backend.

Amount and replay

Amounts use integer ETB minor units. Exact matching is the default. Host expectations can set separate fixed or percentage allowances for underpayment and overpayment. The SDK reports the accepted range and difference.

Replaying the original committed evidence returns the stored outcome without a provider lookup. A bound key used with different or malformed evidence returns IDEMPOTENCY_CONFLICT. A provider timeout is UNAVAILABLE with PROVIDER_TIMEOUT. A missing or blocked Chromium runtime is RECEIPT_BROWSER_UNAVAILABLE at receipt_rendering.

Storage and validation

Use a fresh store for this candidate. PostgreSQL, MySQL and local SQLite use the existing SQL, Drizzle and Prisma adapter contracts. See the tested database and adapter matrix. Existing stores require a tested claim-preserving cutover. Use the synthetic playground to exercise comparisons and see the benchmark observations for measured workload scope.

Troubleshooting

Check the provider, input format and immutable order when input is rejected. For CBE, use the pinned Playwright Chromium and a working OS sandbox. See the CBE runtime requirements and the candidate changelog.
