Benchmark observations

Measured on 19 November 2026 using SDK 0.2.0 source candidate f441981. Each row came from one bounded run on a shared VPS.

Tested environment

Four AMD EPYC virtual CPUs, 7.75 GiB host RAM, Ubuntu 26.04.1 LTS, Linux 7.0.0, Docker 29.1.3 and Compose 2.40.3. The backend container was capped at two vCPUs and 768 MiB. The workload used Node.js 26.13.1 and SQLite 3.54.1 through the direct SQL adapter on an ext4-backed Docker volume.

Each workload used 10 warm-up scenarios, 3 ms mock provider delay and a 50 ms timeout budget. Attempt latency uses nearest-rank percentiles after warm-up. The recovery workload intentionally produced provider timeouts in 25% of attempts and exercised replay and lost-commit-response recovery. Every row completed its expected outcome assertions. Process CPU averaged 0.64 to 1.12 cores across the rows.

Chromium and hosting

A separate sandbox check measured about 1.20 seconds to launch Chromium 159.0.8154.6 (Playwright 1.65.1) and 0.36 seconds to render a small local page. Container memory increased from about 136 MiB to 295 MiB during that probe.

For a similar internal trial, start with concurrency 1 within the tested container allocation and measure on the target volume before raising concurrency. At concurrency 4, successful receipts had higher throughput and a higher p95 than at concurrency 1. These trials cover synthetic SDK work and a local browser probe. Live provider latency, production capacity and minimum hardware requirements remain unmeasured.
